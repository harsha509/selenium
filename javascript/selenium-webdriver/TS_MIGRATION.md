# TypeScript migration guide for maintainers

Status as of 2026-09-05. Branch `ts-migration-2026` on the `harsha509/selenium` fork,
also fast-forwarded onto that fork's `trunk`. This work is not proposed to SeleniumHQ.

## 1. What is done

- Every shipped module of `selenium-webdriver` is TypeScript (`*.ts`) compiled with
  `strict: true`. 87 modules, 16 commits, starting from SeleniumHQ trunk `bdba26c1c6`.
- The published package is unchanged in layout: the same `.js` files at the same paths,
  CommonJS, plus one `.d.ts` per module. No `.ts` source is published.
- `package.json` declares `"types": "./index.d.ts"`.
- API docs are generated by typedoc (`bazel run //javascript/selenium-webdriver:docs`).
- Compatibility of every import style is verified by script (section 4).

Intentionally still JavaScript:

| Path | Why |
| --- | --- |
| `test/**` | Tests load the built package through `selenium-webdriver/...`; keeping them JS proves the compiled output. |
| `lib/test/*` | Test helpers required relatively by the JS tests. |
| `tools/init_jasmine.js` | Bootstrap executed directly by node. |
| `example/*` | Runnable user samples against the published package. |
| `eslint.config.js`, `lib/atoms/make-atoms-module.js` | Tooling. |

## 2. How the build works

1. `ts_project(name = "ts-src")` in `BUILD.bazel` compiles every `*.ts` (excluding
   `test/`, `node_modules/`, `*.d.ts`) in place: `lib/foo.ts` -> `lib/foo.js` + `lib/foo.d.ts`.
   Deep imports such as `require('selenium-webdriver/lib/foo')` therefore keep resolving.
2. `npm_package(name = "selenium-webdriver")` collects the compiled output together with
   `package.json`, `README.md`, `CHANGES.md` and the remaining JS files.
3. `tsconfig.json`: target `es2022`, `module`/`moduleResolution` `nodenext`, `strict`,
   `declaration`, `rootDir: "."`. The package has no `"type": "module"`, so emit is CommonJS.
4. Lint: typescript-eslint 8 over `**/*.ts` (`eslint.config.js`), prettier over both.
   `eslint-plugin-n` resolves `.ts` through `settings.n.tryExtensions`.
5. Generated BiDi modules (`bidi/generated_src/*.ts`) compile through their own rule and
   are excluded from `tsconfig.json`; they do not import the hand-written BiDi layer.
6. Release: unchanged. `./go node:release` publishes `//javascript/selenium-webdriver:selenium-webdriver.publish`.

Gate to run after any change:

```shell
bazel build //javascript/selenium-webdriver:selenium-webdriver
bazel test //javascript/selenium-webdriver:small-tests \
           //javascript/selenium-webdriver:eslint-test \
           //javascript/selenium-webdriver:prettier-test \
           //javascript/selenium-webdriver:bidi-schema-tests
bazel test //javascript/selenium-webdriver:test-builder-test.js-chrome   # needs Chrome
```

## 3. Conventions

Runtime export shape of every module must equal the last JavaScript release.

- No `export default` for real API. The one exception is the alias at the bottom of every
  named-export module (`const defaultExport: typeof self = self; export default defaultExport`),
  which keeps `import x from 'selenium-webdriver/...'` working under `esModuleInterop` and Babel.
- Modules that were `module.exports = Class` use `export = Class`. Attached properties are set
  as expandos and also assigned through `module.exports.X = X` so Node ESM can `import { X }`.
- JavaScript enums become `export const X = { ... } as const` plus `export type X = (typeof X)[keyof typeof X]`.
- Closure-style `@template` results become generics instead of casts:
  `caps.get<T>()`, `driver.execute<T>()`, `bidi.send<T>()`.
- `declare` fields for properties that must not be emitted as own properties; `#private` where
  the JS used WeakMaps; `private`/`protected` where subclasses or tests read the field.
- Interfaces that describe not-yet-typed peers stay small and local to the module that needs them.
- Escape hatches, each documented inline: `@ts-expect-error TS2417` on the four driver classes
  whose static `createSession` differs from `WebDriver.createSession`; `any[]` rest constructors
  in the two mixins of `index.ts` (TypeScript requires them); class + interface merge for
  `ThenableWebDriver`; the `createDriver` cast that mirrors trunk's Closure assertion.
- JSDoc stays on public APIs without `{Type}` tags; the TypeScript signature is the type.
- Imports at the top of the file, one statement per source.

## 4. Compatibility verification

Baseline: a copy of the last JavaScript sources, built from commit `bdba26c1c6`.

```shell
BASE=/tmp/js-baseline
mkdir -p "$BASE"
git archive bdba26c1c6 javascript/selenium-webdriver | tar -x -C "$BASE"
# The baseline needs the compiled atoms next to it:
cp bazel-bin/javascript/selenium-webdriver/selenium-webdriver/lib/atoms/*.js \
   "$BASE/javascript/selenium-webdriver/lib/atoms/"
```

Step 1. Export shapes and import styles. Compares, for all 87 modules in
`tools/ts-migration/modules.js`: `require()` keys, TypeScript/Babel default import, Node ESM
default and named imports.

```shell
NM=$(cd bazel-bin/javascript/selenium-webdriver/node_modules && pwd -P)
NODE_PATH=$NM node javascript/selenium-webdriver/tools/ts-migration/compare_imports.js \
  "$BASE/javascript/selenium-webdriver" bazel-bin/javascript/selenium-webdriver/selenium-webdriver
```

Expected: 2 mismatches, both `lib/proxy` and `proxy`. Trunk's file assigned `exports.Config`
and three other typedef placeholders before replacing `module.exports`, so Node's lexer
advertised ESM names that were always `undefined`. Not reproduced on purpose.

Step 2. Declarations versus the community types.

```shell
TARBALL=$(bazel run -- @pnpm//:pnpm view @types/selenium-webdriver dist.tarball | tail -1)
mkdir -p /tmp/dt && curl -sL "$TARBALL" | tar -xz -C /tmp/dt
TSD=$(find -L bazel-bin/node_modules/.aspect_rules_js -maxdepth 1 -name 'typescript@5*' | head -1)/node_modules/typescript
node javascript/selenium-webdriver/tools/ts-migration/diff_types.js /tmp/dt/selenium-webdriver \
  bazel-bin/javascript/selenium-webdriver/selenium-webdriver "$TSD" > /tmp/types_diff.md
```

The script reports missing exports, missing members, arity changes and declarations where the
community type was `any` and ours is not. Rows for type aliases (`ILocation`, `ITimeouts`, ...)
show as "missing member" because the script only expands classes and interfaces; ignore them.
Section 6 records the decisions taken on the remaining rows.

Step 3. Browser tests that cover converted code and run locally:
`test-builder-test.js-chrome`, `test-remote-test.js-chrome`, `test-edge-options-test.js-chrome`,
`test-firefox-options-test.js-chrome`, `test-ie-options-test.js-chrome`,
`test-bidi-browsingcontext-test.js-chrome`. `test-chrome-options-test.js-chrome` has two
extension-install failures that also fail on the JavaScript baseline in this environment.

## 5. Intentional runtime behavior changes

All were forced by typing, all sit on error or validation paths, and all belong in the
release notes.

| Where | Before | After |
| --- | --- | --- |
| `net/portprober.findFreePort` | Resolved with the string `'Unable to find a free port'` | Rejects with an `Error`, as its doc always said |
| `bidi/browsingContext.create` | `(!x) instanceof CreateContextParameters` never threw | Validates the parameter type |
| `bidi/browsingContext.checkErrorInScreenshot` | Read a `msg` field that does not exist | Reads `message`; errors carry the real text |
| `bidi/browsingContext.locateElement(s)` | Built a `WebElement` with a `null` id | Throws `TypeError` when a node has no `sharedId` |
| `bidi/input.perform` | Mutated the caller's action objects | Sends copies; same wire payload |
| `bidi/cookieFilter.sameSite` | `instanceof` on a plain object | Validates against the allowed values |
| `bidi/browsingContextInspector.close` | Passed five arguments to `unsubscribe(events, contexts)` | Passes two |
| `common/driverFinder` | Ran Selenium Manager with an undefined browser name | Throws `TypeError` first |
| `remote.DriverService.start` | `spawn(undefined)` failure | Rejects with "Executable path has not been set" |
| `firefox.Options.addArguments` | Stored the raw rest array on first call | Flattens once, like the `concat` path |
| `testing` log prefixes | `isatty(process.stdout)` was always false | Colored when stdout is a TTY |
| `testing.getAvailableBrowsers` | Stored `capabilities: undefined` | Omits the key |

## 6. Type-level changes versus `@types/selenium-webdriver`

Compared against 4.35.6 (the community package trails the runtime by 13 releases).

Kept, because they are correct and the migration path is trivial:

| Declaration | Community | Ours |
| --- | --- | --- |
| `Capabilities.get`, `Options.get` | `any` | `get<T = unknown>(key): T` |
| `Session.getCapability`, `Command.getParameter` | `any` | `unknown` |
| `Command.getParameters` | `any` | `Record<string, unknown>` |
| `Executor.execute` | `Promise<any>` | `Promise<unknown>` |
| `Driver.getNetworkConditions` | `Promise<any>` | `Promise<unknown>` |
| `createCDPConnection` | `Promise<any>` | `Promise<CDPConnection>` |
| `HttpClient` constructor | 3 parameters | 4, matching the runtime |
| `Keyboard` constructor | `(type, id)` | `(id)`, matching the runtime |

Added for compatibility: root type-only exports `Locator`, `ByHash`, `Actions`, `ProxyConfig`,
`Alert`, `Navigation`, `Options`, `TargetLocator`, `Window`, `Logs`; aliases `ILocation`, `ISize`,
`IRectangle`, `ITimeouts`, `IWebDriverOptionsCookie`; type-only `ShadowRootPromise` and
chromium `Extensions`.

Not reproduced: names that never existed at runtime on trunk (`TouchSequence`, `Listener`,
`EventEmitter`, the `chromium` namespace on the root, `http` internals, `bidi/remoteValue`,
63 legacy `Command.Name` entries, `WebElement.getSize`/`getLocation`, `Window.getPosition`),
private-by-convention members (`name_`, `level_`, `execute_`), and `I`-prefixed interfaces for
the enum objects (`IBrowser`, `ICapability`, ...).

Known trunk oddity kept as is: `ShadowRoot.findElement` returns a `ShadowRootPromise`.

## 7. Remaining work, in order

1. Release dry run: `bazel build --config=release //javascript/selenium-webdriver:selenium-webdriver`
   and `./go node:release[dry-run]`, then inspect the tarball for `.js` + `.d.ts` only.
2. Sync with SeleniumHQ trunk. Fetch upstream, merge or rebase, and for every upstream change to
   a `.js` file that is now `.ts`, port the change by hand (section 8), then rerun sections 2 and 4.
3. Typedoc link sweep: 252 `{@link}`/`{@linkplain}` targets written in Closure style
   (`#method`, `./module.Name`) do not resolve. Rewrite them to typedoc syntax.
4. Document the generated BiDi modules (`bidi/generated_src`) in typedoc; they are excluded today.
5. After the first release with bundled types, open the DefinitelyTyped PR that deprecates
   `@types/selenium-webdriver` with a pointer to the package.
6. Decide on the optional aliases not added yet: chrome/edge `IOptionsValues` and
   `IPerfLoggingPrefs` (ours are `chromium.ChromiumOptionsDict` and `chromium.PerfLoggingPrefs`).
7. Optional: convert `lib/test/*` (requires adding compiled output to every test target's data),
   `tools/init_jasmine.js` and `example/*`.
8. Optional: turn `compare_imports.js` into a Bazel test by checking a baseline export manifest
   into the repo instead of rebuilding the JavaScript copy.

## 8. Converting or porting a module

1. `git mv lib/foo.js lib/foo.ts`; keep the license header and the JSDoc.
2. Mirror the runtime export shape exactly (section 3). Confirm consumers in `test/` and other
   modules: `rg "lib/foo" javascript/selenium-webdriver`.
3. Type what the code does, not what the JSDoc claimed; where the JSDoc and the code disagree,
   keep the runtime behavior and note it.
4. Prefer a generic or a type guard over a cast. A cast needs a comment saying what the caller asserts.
5. Add the default alias block at the bottom (or `export =` for single-class modules).
6. Run prettier, the gate (section 2) and the two scripts (section 4).
7. Add the module to `tools/ts-migration/modules.js` if it is new.
